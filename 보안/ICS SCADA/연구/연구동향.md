## 1. 위협 동향 (정부기관 공동 권고 기준)

### 1-1. 사전 잠입: Volt Typhoon (2024~)

- CISA · NSA · FBI 공동 권고 **AA24-038A** (2024.02)
- 중국 정부 지원 그룹이 IT망에 잠복하면서 **OT 자산으로 옮겨 가 기능을 방해할 준비**를 한다고 높은 신뢰도로 평가
- 대상: 통신 · 에너지 · 교통 · 상하수도. 일부 환경에서는 최소 5년간 접근 유지
- 침투 경로: 라우터 · VPN · 방화벽 취약점, 이후 시스템 기본 도구만 쓰는 은닉(Living off the Land)
- 2026년에도 CISA는 OT 제로트러스트 가이드에서 Volt Typhoon을 OT 측면 이동의 대표 사례로 다시 언급

### 1-2. 인터넷 노출 PLC 공격: 이란 연계 그룹 (2023 → 2026)

| 시기 | 권고 | 내용 |
| --- | --- | --- |
| 2023.11 | **AA23-335A** | CyberAv3ngers(IRGC 연계)가 기본 비밀번호로 Unitronics PLC 75대 이상 장악. 화면 변조 위주 |
| 2026.04 → 07 개정 | **AA26-097A** | Rockwell CompactLogix · Micro850 → 7월 개정에서 Schneider M340 · Siemens S7-1200까지 확대 |
| 2026.07.30 | CISA 경보 + FBI · EPA PSA | 7월 한 달 동안 **상하수도 기관 100곳 이상** 공격. 비밀번호 바꿔 운영자 잠금, 끓여 마시라는 공지 · 수동 운전 장기화 |
| 2026.08.19 | **AA26-231A** | Siemens S7-200~1500 전 계열 대상 정찰. **AI로 만든 Python 스크립트(snap7)** 사용 확인 |

**AA26-097A 핵심 (2026)**
- 취약점이 필요 없다. **정상 엔지니어링 SW(Studio 5000 등)로 정상 접속**해서 프로젝트 파일을 빼내고 바꾼다
- 한 피해 기관에서 FBI가 찾은 것: 기존 래더 로직은 그대로 두고 **안전 운전 범위를 지키는 명령을 덮어쓰는 로직을 추가** → 정지 · 경보 로직이 꺼져 운영자 모르게 위험 상태로 진입 가능
- 재사용 코드 모듈(**AOI**, 다른 벤더의 함수 블록에 해당)을 변조 → 그 모듈을 쓰는 모든 공정으로 퍼짐. 7월 개정에서 AOI 변조 탐지 지침 추가
- 셀룰러 모뎀에 Dropbear SSH 설치해 원격 유지. 확인된 포트: 22 · 102 · 502 · 2222 · 44818
- 2023년 캠페인과 달리 **실제 운영 중단과 금전 손실** 발생 (Trend Micro 분석)

**AA26-231A 핵심 (2026)**
- 공격자 미지정. "향후 실제 피해를 위한 지속적 정찰"로 평가
- Censys · ZoomEye로 노출 장비 수색 → AI 도움으로 익스플로잇 개발 → 정상 모니터링 SW로 위장
- 대응: TCP 102 경계 차단, PLC 보호 레벨 · 비밀번호 설정, S7comm 쓰기 동작 감시

### 1-3. 노출 규모

- Trend Micro(2026.07): 인터넷에서 바로 닿는 ICS 장비 약 **7.4만 대**. 예전 약 12만 대보다 줄었지만 여전히 많다
- CISA: 서류에 없는 **셀룰러 모뎀**(운영자 · 협력사 · 통합사가 설치)이 노출 원인으로 자주 나온다

## 2. 정책 · 가이드 동향

### 2-1. 미국 · 동맹국 공동 가이드 (2025.12 ~ 2026)

| 발행 | 문서 | 핵심 |
| --- | --- | --- |
| 2025.12.03 | **AI를 OT에 안전하게 통합하는 원칙** (CISA · 호주 ASD 주도, NSA · FBI · 영 · 캐 · 독 · 네 · 뉴 참여) | 4원칙: AI 이해 → OT 내 사용 평가 → 거버넌스 → 안전 · 보안 내장(사람의 감독 유지) |
| 2026.01.14 | **OT 안전 연결 원칙** (영국 NCSC 주도, CISA · FBI) | OT로 들어오는 연결을 설계 · 보호 · 관리하는 8원칙 |
| 2026.04.29 | **OT에 제로트러스트 원칙 적용** (CISA · 전쟁부 · DOE · FBI · 국무부) | IT용 제로트러스트를 그대로 OT에 넣을 수 없다. 자산 가시성, 구역 · 도관, 공급망, ID · 접근 관리. 안전 · 가용성 우선 |
| 2026.05.05 | **CI Fortify** 발표 (CISA) | 공격 중에도 서비스를 계속하는 것: **격리(Isolation) + 복구(Recovery)** |
| 2026.07.28 | **CI Fortify – 핵심 시스템 격리 지침** (CISA · ASD · NCSC · CCCS) | 통신 · 인터넷 · 벤더가 없다고 가정하고, 공격자가 이미 OT 안에 있다고 가정한 단계적 격리 계획 · 훈련 |
| 2026.10 | **제로트러스트로 OT 강화** (NSA 사이버보안 정보지, 미 전쟁부) | 4월 CISA 가이드를 이어받은 실무 강화 지침 |

> 흐름: **"막아라" → "공격 중에도 돌아가게 하라"**. 망 분리만으로는 부족하다는 전제로 격리 운전 · 복구 능력을 요구한다.

### 2-2. NIST SP 800-82 Rev.4 초안 (2026)

| 일정 | 내용 |
| --- | --- |
| 2026.01.22 ~ 02.23 | 사전 의견 수렴 |
| 2026.09.21 | **Rev.4 초안 공개** |
| 2026.11.30 | 의견 마감 (조사일 기준 5일 남음) |

- 확장 내용: 자산 관리, 네트워크 모니터링 · 탐지, **시스템 관리 기능 보호 + 제로트러스트 적용** 아키텍처, 빌딩 자동화 분야 추가
- 구조 변경: OT 오버레이(부록 F)를 별도 문서로 분리, 일부 부록은 웹 자료로 이동
- 현재 확정판은 여전히 **Rev.3 (2023.09)**
- NCCoE: SP 1339 OT 백업 빠른 시작 가이드 별도 발행

### 2-3. 유럽

- **ENISA 2026 EU 사이버보안 현황 보고서** (2026.11.10): NIS2 · 사이버복원력법(CRA) · AI법의 정합을 권고하고, NIS2를 기준으로 사고 보고 양식을 통일하자고 제안
- 2026.01 EU 집행위원회 **새 사이버보안법(Cybersecurity Act) 개정안** 제안
- OT 측면 정리: NIS2는 **운영 조직**, CRA는 **디지털 제품(PLC · HMI 포함)**을 규제. 기술 요건은 IEC 62443로 맞추는 흐름

### 2-4. 국내

- **KISA OT 환경 제로트러스트 적용 안내서** (2025.12): 국내 첫 OT 제로트러스트 지침. Purdue 모델 계층별로 제로트러스트 가이드라인 2.0의 6대 핵심요소 요구사항을 제시 → [[보안/제로트러스트/연구/자료]]
- **KISA OT 보안 리빙랩 개편** (2025.12~): 5곳 → 2곳으로 통합, "OT 제품 통합보안지원센터" 체계로 전환
- 2026년 국정원 · KISA의 새 OT 전용 가이드는 조사 시점에 확인되지 않음

## 3. 산업 · 포럼 보고서

### WEF 세계 사이버보안 전망 2026 (2026.01.12)

- 조직의 **64%**가 지정학적 동기의 공격(기반시설 방해 · 첩보)을 위험 계획에 반영
- 공공 부문의 **23%**가 사이버 복원력이 부족하다고 응답
- WEF 기고들의 공통 메시지: **AI를 OT에 빠르게 들이기 전에 가시성 · 모니터링부터** 확보하라. 북미 전력 규제 CIP-015-1이 내부망 트래픽 감시를 의무화한 것을 사례로 듦

### Fortinet OT 현황 보고서 2025 (2025.07, OT 실무자 550명+ 설문)

| 지표 | 이전 | 2025 |
| --- | --- | --- |
| OT 보안을 CISO가 책임 | 16% (2022) | **52%** |
| C레벨이 OT 책임 | 41% (2022) | **95%** |
| 매출에 영향 준 운영 중단 | 52% (2024) | **42%** |
| 가시성 확보 + 세그멘테이션 구현 | 20% | 26% |

- 해석: OT 보안이 공장 현장 문제에서 **경영진 · CISO 책임**으로 올라왔다. 성숙도가 높을수록 침입이 적다
- 가장 많이 공격받는 업종은 여전히 **제조업**

## 4. Black Hat에서 본 ICS · SCADA 연구 흐름

Black Hat 일정표 페이지는 직접 열리지 않아(403), Black Hat 공식 페이지 검색 결과와 발표사 공식 페이지로 확인한 것만 적었다.

### 역대 흐름

| 연도 | 발표 | 의미 |
| --- | --- | --- |
| USA 2011 | Beresford, *Exploiting Siemens Simatic S7 PLCs* | Stuxnet 이후 PLC 공개 익스플로잇의 시작. 지금도 논문에 자주 인용 |
| USA 2015 | Klick 외, *Internet-facing PLCs – A New Back Orifice* | **인터넷에 노출된 PLC에 임의 코드 적재** → 2026년 AA26-097A 상황을 11년 전에 예고 |
| USA 2019 | Technion · 텔아비브대, Siemens S7 연구 | S7 PLC들이 같은 암호 키쌍을 공유, 가짜 엔지니어링 스테이션으로 로직 몰래 주입 |
| Europe 2021 | *Greetings from the '90s: Exploiting the Design of Industrial Controllers in Modern Settings* | 컨트롤러 설계 자체의 구조적 결함 |
| Europe 2024 | Zaltzman · Wool, *From Pass-the-Hash to Code Execution on Schneider Electric M340 PLCs* | Modicon 암호 프로토콜 분석 → 엔지니어링 스테이션 사칭 + 메모리 버그로 원격 코드 실행 · 루트킷 |
| USA 2025 | **ICS 마이크로 서밋** (8.7) | 산업용 IoT를 OT망에 연결할 때의 보안이 주제 |
| USA 2025 | 핵심 기반시설 패널 | OT 공격이 갈취 · 첩보에서 **파괴**로 이동. 공격자는 최신 AI · 제로데이가 필요 없다 — OT가 그만큼 취약하기 때문 |
| USA 2026 | Nozomi Networks, *Deterministic Chaos – Exploiting and Securing Predictable Timing in TSN Industrial Networks* (온디맨드) | 차세대 산업망 **TSN**(시간 민감형 네트워킹) 타이밍 조작. 대상: Mitsubishi CC-Link IE TSN. 당장의 대책은 TSN망 강한 세그멘테이션 |
| USA 2026 | Arsenal: *ICSForge – OT/ICS Security Coverage Validation Platform* | OT 탐지 범위를 검증하는 도구 |

### Black Hat에서 읽히는 경향

```
2011–2019:  PLC 자체 익스플로잇 (펌웨어 · 프로토콜 · 암호)
2021–2024:  설계 결함 · 엔지니어링 스테이션 사칭 · 인증 우회
2025–2026:  파괴 목적 공격 현실화 · 차세대 산업망(TSN) · 탐지 범위 검증 도구
```

- 연구가 먼저 보여 준 공격(인터넷 노출 PLC, 엔지니어링 스테이션 사칭)이 **5~10년 뒤 실제 정부 권고로 나타난다**
- 2026년 Nozomi 발표는 모회사(2026.01 Mitsubishi Electric 인수)의 프로토콜을 분석한 것 — 벤더와 연구 조직이 붙어 있는 구조도 눈여겨볼 점

| 격리 운전 · 복구 | CI Fortify(2026.05 · 07) | 외부 의존 없이 돌아가는 단계적 격리 계획 + 오프라인 로직 백업 |
| 규제 강화 | NIS2 · CRA, ENISA 2026 | 제품(CRA)과 운영(NIS2) 양쪽 대응, IEC 62443 기반 |
| 차세대 산업망 공격면 | Black Hat 2026, ECRTS 2026 | TSN 도입 시 세그멘테이션 · 시간 동기 무결성 |

## 점검 목록

- [ ] 인터넷에서 닿는 PLC · HMI · 셀룰러 모뎀이 없는가 (Shodan · Censys로 자기 IP 확인)
- [ ] PLC 실행 로직을 정상본과 정기적으로 비교하는가 (AOI · 함수 블록 포함)
- [ ] 안전 · 경보 로직이 바뀌면 알림이 오는가
- [ ] 외부 통신 · 벤더 없이 핵심 공정을 돌리는 격리 운전 계획을 훈련했는가
- [ ] 엔지니어링 SW 접속을 허용 목록 + MFA로 제한하는가
- [ ] AI를 OT에 들인다면 사람이 최종 판단하는 구조인가
