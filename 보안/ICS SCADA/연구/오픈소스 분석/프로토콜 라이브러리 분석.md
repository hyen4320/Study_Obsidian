## 1. pymodbus (Modbus, Python)

### 1.1 계층 구조

| 계층 | 추상화 | 위치 |
|---|---|---|
| 전송 | `ModbusProtocol(asyncio.BaseProtocol)` + `CommParams` + `CommType{TCP,TLS,UDP,SERIAL}` | `pymodbus/pymodbus/transport/transport.py:70,80,108` |
| 프레이밍(ADU) | `FramerBase` (`decode`/`encode`/`buildFrame`/`handleFrame`) | `pymodbus/pymodbus/framer/base.py:26,40,51,70,79` |
| 트랜잭션 | `TransactionManager(ModbusProtocol)` — 재시도·락·TID·trace 훅 | `pymodbus/pymodbus/transaction/transaction.py:17` |
| 애플리케이션(PDU) | `ModbusPDU` 베이스 + `DecodePDU` 함수코드 레지스트리 | `pymodbus/pymodbus/pdu/pdu.py:13`, `pymodbus/pymodbus/pdu/decoders.py:14` |
| 데이터 모델 | `SimCore` → `SimRuntime` ← `SimDevice`/`SimData` (구형: `ModbusServerContext`/`ModbusDeviceContext`, deprecated 경고 출력) | `pymodbus/pymodbus/simulator/simcore.py:14`, `simruntime.py:15`, `simdevice.py:25`, `simdata.py:26`, `pymodbus/pymodbus/datastore/context.py:18,75,66-72,121-126` |
| 사용자 API | 클라이언트 `ModbusClientMixin`(read_coils 등), `ModbusBaseClient`/`ModbusBaseSyncClient`; 서버 `ModbusBaseServer` 및 Tcp/Tls/Udp/Serial 서버 | `pymodbus/pymodbus/client/mixin.py:59-857`, `client/base.py:51,157`, `server/base.py:21`, `server/server.py:16,80,146,207` |

계층 경계:
- 전송 ↔ 상위: 추상 콜백 4개 `callback_new_connection` / `callback_connected` / `callback_disconnected` / `callback_data(data, addr) -> int`(소비 바이트 수 반환) (`transport.py:330-342`). 전송은 "내용을 모르는 파이프"라고 모듈 docstring 이 명시한다(`transport.py:45-47`).
- 프레이머 ↔ PDU: `FramerBase.__init__(decoder: DecodePDU)`(`framer/base.py:33-38`), `handleFrame` 이 `decode()` 로 (used_len, dev_id, tid, frame_data)를 얻은 뒤 `self.decoder.decode(frame_data)` 호출(`base.py:88,103`).
- PDU ↔ 데이터 모델: `ModbusPDU.datastore_update(context, device_id)`(`pdu/pdu.py:93-100`)를 서버 핸들러가 호출(`server/requesthandler.py:99,101`). 컨텍스트 인터페이스는 `async_getValues(device_id, func_code, address, count)` / `async_setValues(device_id, func_code, address, values)` (`simulator/simcore.py:52-70`).
- 서버는 연결마다 `ServerRequestHandler(TransactionManager)` 를 생성(`server/base.py:71-75`, `server/requesthandler.py:17`).

### 1.2 핵심 추상화와 구현체

- `FramerBase` 구현체: `FramerSocket`(MBAP, `framer/socket.py:9`), `FramerTLS`(Socket 과 동일, `socket.py:63-67`), `FramerRTU`(CRC16, `framer/rtu.py:9`), `FramerAscii`(`framer/ascii.py`, 내부 미확인). 선택 테이블 `FRAMER_NAME_TO_CLASS`(`framer/__init__.py:18-23`), `FramerType` enum(`framer/base.py:17-23`).
- `ModbusPDU` 하위 구현: `x_encode()`/`x_decode()`/`x_calculateRtuFrameSize()` 추상 메서드(`pdu/pdu.py:85-105`). 메시지군 파일: `bit_message.py`, `register_message.py`, `diag_message.py`, `file_message.py`, `mei_message.py`, `other_message.py`, `exceptionresponse.py`.
- `DecodePDU`: 클래스 레벨 `pdu_table`/`pdu_sub_table`(`decoders.py:17-18`), `add_pdu`/`add_sub_pdu`(`:42,47`), 사용자 정의 PDU 등록 `register(custom_class)`(`:53-62`). 서버는 `custom_pdu` 인자로 등록(`server/base.py:46-48`).
- trace 훅: `trace_packet(sending, bytes)->bytes`, `trace_pdu(sending, pdu)->pdu`, `trace_connect(bool)`(`transaction/transaction.py:42-44,57-59`). 문서 주석이 "trace 메서드로 데이터스트림/PDU 를 수정할 수 있다"고 명시(`client/tls.py:38-39`).
- `NullModem`: 소켓/시리얼을 대체하는 in-process 전송(테스트용)(`transport/transport.py:482`, 설명 `:38-43`).

### 1.3 플랫폼 추상화

별도 HAL 없음. asyncio(`loop.create_server`/`create_connection`/`create_datagram_endpoint`, `transport.py:185-216`)와 pyserial 래퍼(`transport/serialtransport.py`, `create_serial_connection` 을 `transport.py:64` 에서 import; 내부 구현은 미확인)에 의존한다. 동기 클라이언트는 `ModbusBaseSyncClient`(`client/base.py:157`)로 별도 제공.

### 1.4 데이터 모델

- 레지스터 블록: `SimData(address, count, values, datatype, string_encoding, readonly)`(`simulator/simdata.py:108-137`). `SimDevice(id, simdata, use_bit_addressing, identity, action)`(`simdevice.py:57-115`): 공유 블록 1개 또는 (coils, discrete inputs, holding, input) 4블록 튜플(`simdevice.py:59-70`).
- 런타임 표현: 블록별 `(start_address, register_count, registers: list[int], flags: list[int])`(`simruntime.py:37,59`). 함수코드→블록 매핑 `_fx_mapper`(`simruntime.py:18-30`).
- 품질(quality)·타임스탬프: 없음(레지스터 값 + datatype/readonly 플래그만 존재, `simruntime.py:62-66`).
- 이벤트/보고(unsolicited/subscription): 없음. 확인한 서버 경로는 요청-응답뿐(`server/requesthandler.py:92-120`). `pdu/events.py` 는 미확인.
- 다중 장치: device id → `SimRuntime` 맵, id 0 은 미정의 id 의 대체(`simcore.py:35-43`). broadcast(dev_id 0) 옵션(`server/requesthandler.py:95-100`).

### 1.5 제어(쓰기) 처리

- SBO 개념 없음(확인한 코드 범위에서 select/operate 추상화 없음).
- 쓰기 검증: (1) 주소 범위 → `ILLEGAL_ADDRESS`(`simruntime.py:90-91,115-116`), (2) `INVALID` 타입/`readonly` 플래그 → `ILLEGAL_ADDRESS`(`simruntime.py:62-66`), (3) 사용자 훅 `action(function_code, start_address, address, count, current_registers, set_values) -> ExcCodes | None` — 읽기·쓰기 모두 호출되며 값 변경이나 예외코드 반환 가능(`simdevice.py:91-115`, 호출부 `simruntime.py:67-72`).
- 클라이언트측 API 인자 검증: `verifyCount`/`verifyAddress`(`pdu/pdu.py:57-69`), 예: `register_message.py:30-31,98-99,188-191`.

### 1.6 보안

- 암호화: Modbus/TCP over TLS 지원. `CommParams.sslctx: ssl.SSLContext`(`transport.py:94`)를 `create_server`/`create_connection` 의 `ssl=` 로 전달(`transport.py:204,215`). 서버 `ModbusTlsServer` 는 `sslctx` 가 없으면 `TypeError`(`server/server.py:120-123`). 클라이언트 `AsyncModbusTlsClient` 기본 `sslctx = ssl.SSLContext(ssl.PROTOCOL_TLS_CLIENT)`, 기본 포트 802(`client/tls.py:64,66`). 그 기본 컨텍스트의 검증 동작은 Python 표준 라이브러리 소관이라 이 저장소 코드로는 미확인.
- 인증·접근통제(역할 기반 등): 없음. `pymodbus/pymodbus` 전체에서 `role|authori|authent` 검색 결과 0건. 접근통제에 준하는 것은 `readonly` 플래그와 `action` 훅뿐.
- 감사: 전용 인터페이스 없음. `trace_*` 훅과 `Log` 클래스만 존재.
- 기본값: 평문 TCP 서버 기본 주소 `("", 502)`(`server/server.py:29`), `source_address` 미지정 시 `0.0.0.0:502` 리슨(`transport.py:147-148`). 즉 기본 구성은 무인증·무암호·전 인터페이스 바인드.

### 1.7 견고성

- 프레임 파싱: MBAP 최소 길이 8, protocol id ≠ 0 이면 버퍼 폐기(`framer/socket.py:25-31`); RTU 는 CRC 검사 실패 시 폐기(`framer/rtu.py:99-101`); `MAX_SIZE = 264`(`framer/base.py:31`), 수신 버퍼가 `max_buffer_size` 초과 시 비움(`transport.py:312-313`, 값 설정 `transaction.py:50`).
- PDU 디코드: 빈 프레임·미지 함수코드·`ValueError/IndexError/struct.error` → `ModbusIOException`(`decoders.py:66-95`); 서버는 이를 `ILLEGAL_FUNCTION` 예외 응답으로 변환(`requesthandler.py:69-78`). 데이터스토어 예외 → `DEVICE_FAILURE`(`:111-117`), 미지 장치 → 무응답 또는 `GATEWAY_NO_RESPONSE`(`:103-110`).
- 타임아웃/재시도: 기본 `timeout=3`, `retries=3`, `reconnect_delay=0.1`, `reconnect_delay_max=300`(`client/tcp.py:71-74`); 재접속 지수 백오프(`transport.py:445-461`); 응답 대기 `asyncio.wait_for`(`transaction.py:224-226`); 연속 무응답 `retries+3` 회 카운터(`transaction.py:60`); dev_id/함수코드/TID 불일치 응답 거부(`transaction.py:228-242`, `framer/base.py:92-101`).
- 연결 수 제한: 없음. `active_connections` dict 에 추가만 함(`transport.py:431`); `backlog|max_conn|max_clients` 검색 0건.
- keep-alive: 확인한 범위에 없음(미확인).
- 로깅: `Log` 클래스가 `logging.getLogger` 래핑(`logging.py:41-79`), 최근 프레임 덤프 `MAX_FRAMES = 20`(`logging.py:50-51`).

### 1.8 암시되는 요구사항

- 프레이밍(RTU/ASCII/MBAP)과 전송(TCP/TLS/UDP/시리얼)은 독립 교체 가능해야 한다(`FRAMER_NAME_TO_CLASS`, `CommType`).
- 벤더 확장 함수코드를 플러그인으로 등록할 수 있어야 한다(`DecodePDU.register`).
- 레지스터 단위의 유효/무효·읽기전용 속성과 쓰기 전 사용자 검증 훅이 필요하다(`SimData.readonly`, `SimDevice.action`).
- 프로토콜 자체에 인증이 없으므로 TLS 는 선택 사항으로만 제공되고, 권한 판정은 애플리케이션 훅에 맡겨져 있다.

- "편의 기본값"과 "보안 기본값"이 분리되어 있어, 제품은 보안 프로파일을 명시적으로 선택해야 한다.

### 3.8 암시되는 요구사항

- OS·네트워크·시계·파일·TLS 를 HAL 로 분리해 베어메탈/스레드리스 환경까지 이식해야 한다.

### 4.8 암시되는 요구사항

- 마스터/아웃스테이션 역할별로 "스택이 호출하는 콜백 인터페이스"(SOE 수신, 명령 처리, 애플리케이션 훅)를 분리해야 한다.
- SBO 의 select-operate 일치(내용 동일성·시퀀스·시간)는 사용자 코드가 아니라 스택이 강제해야 한다(`ControlState`).
- 포인트마다 품질 플래그·타임스탬프·이벤트 클래스·데드밴드가 구성 가능해야 한다.
- 통신 이상(주소 불일치, CRC 오류, keep-alive 실패)은 카운터와 콜백으로 관측 가능해야 한다.
- 프로토콜 고유 인증(SAv5)이 없으면 TLS 상호 인증이 유일한 인증 수단이 된다.

## 5. 네 프로젝트를 가로지르는 공통 패턴과 차이

### 5.1 공통 패턴

1. 전송과 프레이밍/링크의 분리: pymodbus `ModbusProtocol`↔`FramerBase`, open62541 `UA_ConnectionManager`↔SecureChannel, libiec61850 `Socket`/`TLSSocket`↔COTP, opendnp3 `IAsyncChannel`↔`ILinkLayer`. 네 곳 모두 TCP 외 매체(시리얼·UDP·이더넷 L2 중 일부)를 같은 상위 계층에 꽂는다.
2. 사용자 로직은 콜백/핸들러로 주입: Python 콜러블(`action`, `trace_*`), C 함수 포인터 + `void* context/parameter`(open62541, libiec61850), C++ 추상 클래스(opendnp3).
3. 디코더는 실패를 예외/상태코드로 격리하고 프로토콜 수준 오류 응답으로 변환: `ModbusIOException`→ExceptionResponse, `UA_STATUSCODE_BADENCODINGERROR`, BER -1 반환, `ParseResult`.
4. 크기·개수·시간 한도가 설정값으로 노출: 프레임/PDU 최대 크기, 타임아웃, 재시도, 재접속 백오프.
5. TLS 는 네 곳 모두 "선택 기능"이고, 가장 단순한 생성 경로는 평문·무인증이다(§1.6, §2.6, §3.6, §4.6).
6. 서버(슬레이브/아웃스테이션) 측에 "쓰기 전 검증 훅"이 존재한다.

### 5.2 차이

| 항목 | pymodbus | open62541 | libiec61850 | opendnp3 |
|---|---|---|---|---|
| 플랫폼 추상화 | 없음(asyncio/pyserial) | EventLoop·clock·crypto 플러그인 (`arch/`) | HAL 8종 (`hal/`) | 없음(asio 의존) |
| 데이터 모델 | 평면 레지스터 + 플래그 | 타입 있는 노드 그래프 | 계층형 LD/LN/DO/DA + FC | 타입별 인덱스 포인트 |

| 프로토콜 고유 인증 | 없음 | SecureChannel 인증서 + 사용자 토큰 | ACSE 인증기(비밀번호/인증서/TLS) | 없음(SAv5 미구현) |

| 구성 시점 | 런타임 인자 | 런타임 config 구조체 + 빌드 플래그 | 컴파일타임 매크로 + 런타임 config | 런타임 config 구조체 |
| 퍼저 | 미확인 | 미확인(`tests/` 미열람) | `fuzz/` 8개 | 미확인 |
