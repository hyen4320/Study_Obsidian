> 제로트러스트 오픈소스 프로젝트 · 구성요소별 정리
> 조사일: 2026-11-22
> 요약: **한 프로젝트로 제로트러스트 전체를 구현하는 경우는 거의 없다.** NIST 800-207의 구성요소별로 골라서 조합한다.
> 관련: [[보안/제로트러스트/연구/자료]] · [[연구 동향]]

## 구성요소 지도

```
정책 입력 (ID · 기기 · 로그)
        ↓
  PDP: 정책 엔진(PE) + 정책 관리자(PA)   ← OPA · OpenFGA · Cedar
        ↓
주체 ──→ PEP ──→ 자원
 ↑        ↑
Keycloak  Pomerium · OpenZiti · Cilium · agentgateway
SPIRE
Keylime
```

## 1. 접근 프록시 · ZTNA (PEP)

| 프로젝트 | 성격 | 라이선스 |
| --- | --- | --- |
| **OpenZiti** | 앱 계층 오버레이. 열린 포트 없음, SDK로 앱에 내장 가능. `mcp-gateway` · `llm-gateway` 하위 프로젝트 있음 | Apache 2.0 |
| **Pomerium** | ID 인식 리버스 프록시 (BeyondCorp 방식). **웹 앱 전용**, SSH · DB 불가 | Apache 2.0 |
| **NetBird** | WireGuard 메시 + SSO · 정책. Tailscale 대체에 가장 가까움 | AGPL |
| **Headscale** | Tailscale 제어 서버 오픈소스 구현 | BSD |
| **Nebula** | Slack이 만든 인증서 기반 메시 | MIT |
| **Authelia** | 리버스 프록시 앞단 SSO · MFA 포털 | Apache 2.0 |
| **Pritunl Zero** | SSH · 웹 특권 접근용 BeyondCorp 서버 | AGPL 계열 |

## 2. ID 제공자 · 사용자 인증

- **Keycloak** (CNCF) — OIDC · SAML · WebAuthn · 조건부 플로우. 사실상 표준
- **ZITADEL** · **authentik** · **Kanidm** · **Ory**(Kratos · Hydra) — 경량 · 클라우드 네이티브
- **privacyIDEA** — MFA 토큰 관리

## 3. 워크로드 ID · PKI (비인간 신원)

- **SPIFFE / SPIRE** (CNCF 졸업) — 워크로드 증명 후 짧은 수명 SVID 자동 발급. **에이전트 ID 연구의 기반**
- **step-ca** (Smallstep) — 짧은 수명 인증서 · SSH 인증서 CA
- **cert-manager** — 쿠버네티스 인증서 자동화

## 4. 정책 엔진 · 인가 (PDP)

| 프로젝트 | 방식 |
| --- | --- |
| **OPA** (CNCF 졸업) | Rego 범용 정책. Envoy · K8s · 게이트웨이 연동 |
| **OpenFGA** · **SpiceDB** | Google Zanzibar 방식 관계 기반 인가(ReBAC) |
| **Cerbos** · **Cedar**(AWS) | 앱 수준 세밀한 인가 |
| **Kyverno** | 쿠버네티스 정책 |

## 5. 마이크로세그멘테이션 · 서비스 메시

- **Cilium** — eBPF, ID 기반 네트워크 정책, 투명 암호화
- **Istio** — 서비스 간 mTLS 자동화, 인가 정책
- **Calico** — 네트워크 정책
- **Linkerd** — 2024년부터 stable 릴리스는 Buoyant 배포. 도입 전 확인

## 6. 기기 신뢰 · 증명

- **Keylime** (CNCF) — TPM 2.0 + IMA 원격 증명, 런타임 무결성. 2026년 푸시 모델 추가
- **Trustee** (Confidential Containers) — Keylime과 함께 증명 분야 양대 프로젝트
- **osquery** · **Fleet** — 기기 상태 수집 → 정책 입력

## 7. 가시성 · 지속 모니터링

- **Falco** · **Tetragon** — eBPF 런타임 위협 탐지
- **Wazuh** — SIEM · XDR
- **OpenTelemetry** — 로그 · 트레이스 표준

## 8. AI 에이전트용 (2026 신생)

| 프로젝트 | 역할 |
| --- | --- |
| **agentgateway** | MCP · A2A 이해하는 게이트웨이. Solo.io → Linux Foundation → AAIF. OPA · Kyverno · OpenFGA · SpiceDB 연동. **에이전트용 PEP** |
| **Kagenti** (Red Hat) | K8s 에이전트 제어 평면. SPIFFE + RFC 8693 토큰 교환. 알파 |
| **IBM MCP Gateway** | 에이전트↔도구 사이 단일 지점에서 정책 · 감사 |
| **OpenZiti mcp-gateway** | 위 1번 참고 |

## 오픈소스 참조 스택

| 역할 | 선택 |
| --- | --- |
| 사람 인증 | Keycloak |
| 워크로드 · 에이전트 ID | SPIRE |
| 기기 증명 | Keylime |
| PDP | OPA 또는 OpenFGA |
| PEP (사용자) | Pomerium · OpenZiti |
| PEP (서비스 간) | Cilium · Istio |
| PEP (에이전트→도구) | agentgateway |
| 정책 입력 · 모니터링 | osquery · Fleet · Falco · Wazuh · OpenTelemetry |

NIST 1800-35의 상용 구현 패턴(EIG · 마이크로세그멘테이션 · SDP)을 오픈소스로 옮긴 형태입니다.

## 점검 목록

- [ ] 라이선스가 OSI 승인 오픈소스인가 (BSL · 상용 CE 아닌가)
- [ ] PEP가 HTTP만 되는지, SSH · DB까지 되는지 확인했는가
- [ ] 정적 API 키 대신 짧은 수명 자격증명(SPIRE 등)을 쓰는가
- [ ] PDP와 PEP가 분리되어 있는가
- [ ] 에이전트를 쓴다면 도구 호출 앞에 PEP가 있는가
