> DaaS 참고 자료 가이드
> 조사일: 2026-11-25
> 출처 기준: 정부기관 · 표준기관, 학회 · 컨퍼런스, 대기업(클라우드 사업자 · 분석기관) 자료만 사용
> 요약: **보안 원칙은 NIST SP 800-46r2 · 800-125, 국내 공공 도입은 CSAP DaaS 인증 + 국정원 N2SF로 잡는다.** 사업자 문서(Microsoft · AWS · Citrix · Omnissa)는 구현 방법으로만 본다.

## 읽는 순서

```
NIST SP 800-46r2   →  NIST SP 800-125 / 125A  →  NIST SP 800-207
 (원격근무 · VDI)       (가상화 · 이미지 · 관리평면)     (제로트러스트 접근)
        ↓
CSAP DaaS 인증 · 국정원 N2SF  →  사업자 보안 문서  →  게이트웨이 취약점 이력(CISA KEV)
 (국내 공공 요건)                  (구현 방법)             (실제 공격 지점)
```

| 단계 | 목적 | 문서 |
| --- | --- | --- |
| 1. 원칙 | VDI가 왜 · 언제 안전한가 | NIST 800-46r2 |
| 2. 가상화 보안 | 이미지 · 하이퍼바이저 · 관리 평면 | NIST 800-125, 800-125A r1 |
| 3. 접근 통제 | 게이트웨이를 PEP로 | NIST 800-207 → [[보안/제로트러스트/연구/자료]] |
| 4. 국내 요건 | 공공 납품 · 도입 | CSAP DaaS, 국정원 N2SF |
| 5. 구현 | 실제 설정 | Microsoft · AWS · Citrix · Omnissa 보안 가이드 |
| 6. 위협 | 실제로 뚫린 곳 | CISA KEV(Citrix NetScaler 등), Black Hat RDP 연구 |

## NIST

| 문서 | 핵심 | 링크 |
| --- | --- | --- |
| **SP 800-46 Rev.2** (2016) | 원격근무 · 원격 접속 · BYOD. VDI는 **BYOD · 외부 단말에 특히 유용**. 세션 종료 시 VM 파기로 단말에 데이터 안 남김. 일반 원격 데스크톱은 위험 분석 후 예외적으로만 | [PDF](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-46r2.pdf) |
| **SP 800-125** (2011) | 서버 · 데스크톱 전체 가상화 보안. 데스크톱 가상화의 핵심 차이는 **이미지 통제**. 관리 시스템 접근 제한, 클립보드 · 파일 공유 기본 차단, 이미지 체크섬 | [csrc.nist.gov](https://csrc.nist.gov/pubs/sp/800/125/final) |
| **SP 800-125A Rev.1** | 하이퍼바이저 배치 보안 권고 (장치 가상화 포함). DaaS 호스트 설계용 | [PDF](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-125Ar1.pdf) |
| **SP 800-207** (2020) | 제로트러스트 아키텍처. DaaS 게이트웨이 = PEP | [csrc.nist.gov](https://csrc.nist.gov/pubs/sp/800/207/final) |
| ITL Bulletin 2020.03 | 800-46r2 권고가 코로나 원격근무 상황에도 유효하다고 재확인 | [csrc.nist.gov](https://csrc.nist.gov/pubs/itlb/2020/03/security-for-enterprise-telework-remote-access-and/final) |

> NIST에는 **VDI · DaaS 전용 문서가 없다.** 800-46r2(접속) + 800-125(가상화) + 800-207(접근 통제)을 조합한다.

## 국내

### CSAP (클라우드 보안인증) — DaaS 유형

| 항목 | 내용 |
| --- | --- |
| 근거 | 「클라우드컴퓨팅 발전 및 이용자 보호에 관한 법률」 제23조의2 |
| 평가 기준 | 「클라우드컴퓨팅서비스 보안인증에 관한 고시」 제15조 |
| 인증 유형 | IaaS · SaaS · **DaaS** (DaaS = 데스크톱(PC)을 서비스로 제공) |
| 인증기관 | KISA |
| 평가기관 | 한국정보통신진흥협회, 한국아이티평가원, 한국시스템보증 |
| 절차 | 신청 → 예비점검 → 계약 → 본점검(현장평가 · 취약점 점검) → 보완 → 이행점검 → 인증위원회 → 발급 |
| 등급 | 상 · 중 · 하 등급제(2024 전면 시행). 기존 DaaS 인증은 **중등급으로 인정**하는 방향으로 발표됨 |
| 공공 사업 | 공공 DaaS 입찰은 CSAP DaaS 인증 보유 사업자로 제한하는 경우가 많다 (예: 우정사업본부 인터넷 PC) |

- 안내: [KISA CSAP 인증 안내](https://www.kisa.or.kr/1050603) · 서식: 클라우드보안인증제 홈페이지(isms-p.or.kr)
- **개편 중**: 공공 클라우드 보안 검증을 국정원 중심 단일 체계로 바꾸는 개편이 진행 중. 새 제도 시행 전까지 기존 CSAP 유지, 기존 인증 유효기간(5년) 인정 → [[보안/클라우드/DaaS VDI/연구/연구동향]]

### 국정원 N2SF (국가 망 보안체계)

- 망분리를 개선한 체계. 업무 정보를 **기밀(C) · 민감(S) · 공개(O)**로 나누고 등급별 보안통제 적용
- DaaS 활용 범위는 등급 · 용도에 따라 달라짐 (원격근무용 업무망 DaaS 허용 입장이 2026년 보도됨 — 원문 확인 필요)
- 상세: [[보안/제로트러스트/연구/자료]]

### 금융

- 금융위원회 **금융분야 망분리 개선 로드맵** (2024.08): 망분리 규제를 단계적으로 완화하고 클라우드 · 생성형 AI 이용 범위 확대. 금융권 VDI · DaaS 설계 시 참고

## 점검 목록

- [ ] 게이트웨이가 패치 최신이고, KEV 등재 시 즉시 대응 절차가 있는가
- [ ] 게이트웨이 앞에 MFA + 조건부 접근(단말 상태 · 위치)이 있는가
- [ ] 클립보드 · 드라이브 · USB · 프린터 리디렉션이 기본 차단, 필요한 사용자만 허용인가
- [ ] 골든 이미지 변경이 승인 · 기록되고, 무결성을 확인하는가
- [ ] 관리 평면(브로커 · 이미지 관리) 접근이 별도 관리자 계정 + MFA로 제한되는가
- [ ] 세션 로그 · 관리자 작업 로그가 SIEM으로 가는가
- [ ] 공공이라면 사업자가 CSAP DaaS 인증을 보유하고, N2SF 등급과 용도가 맞는가
