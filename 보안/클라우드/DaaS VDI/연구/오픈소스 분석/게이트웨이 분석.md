## 1. Apache Guacamole (guacamole-server + guacamole-client)

### 1.1 최상위 구조와 데이터 흐름

```
브라우저(JS) ──HTTP/WebSocket 터널──> 웹앱(Java, REST+터널) ──TCP 4822, Guacamole protocol(선택적 TLS)──> guacd(부모)
                                                                                         └ fork+fexecve ─> 연결당 자식 프로세스
                                                                                              └ dlopen libguac-client-<proto>.so ─> RDP/VNC/SSH/telnet/k8s 원격지
```

- 프로세스 경계는 4단이다: 브라우저, 웹앱, guacd 부모, 연결당 guacd 자식.
- 웹앱→guacd 핸드셰이크 (Java 쪽 `gc-common/protocol/ConfiguredGuacamoleSocket.java`): `select`(220) → `args` 수신(223) → `size`(264) / `audio`(274) / `image`(288) / `timezone`(296) / `name`(303) → `connect`(307) → `ready` 수신(310). `ready` 가 돌려주는 값이 connection ID 이다(338).
- guacd 쪽 대응: `gs/src/guacd/connection.c:301` 에서 `select` 를 기다리고, 인자가 `$` 로 시작하면(`GUAC_CLIENT_ID_PREFIX`, `gs/src/libguac/guacamole/client-constants.h:43`) 기존 연결에 합류(331–333), 아니면 프로토콜 이름으로 새 프로세스 생성(363).
- 핸드셰이크 opcode 테이블: `gs/src/libguac/user-handlers.c:65-70` (`size, audio, video, image, timezone, name`).
- 연결 후 클라이언트→서버 instruction 테이블: `user-handlers.c:39-58` (`sync, touch, mouse, key, clipboard, disconnect, size, file, pipe, ack, blob, end, get, put, audio, argv, nop, usbconnect, usbdata, usbdisconnect`).
- 프로토콜 플러그인은 `libguac-client-` + 이름 + `.so` 를 `dlopen` 하고 `guac_client_init` 심볼을 찾는다 (`gs/src/libguac/guacamole/plugin-constants.h:32,37`, `gs/src/libguac/client.c:685,695`).
- 소스에 있는 프로토콜 디렉터리: `gs/src/protocols/{rdp,vnc,ssh,telnet,kubernetes,serial}`.

### 1.4 확장점

- 새 원격 프로토콜: `libguac-client-<name>.so` 를 만들고 `guac_client_init` 에서 `client->args` 와 join/leave/free 핸들러를 채운다. 사용자 join 시 `guac_user` 핸들러를 꽂는다. 웹 UI 에 노출하려면 프로토콜 JSON 을 추가한다(JSON 로딩 경로의 세부는 미확인).
- 새 인증 방식/저장소: 확장 jar 를 `GUACAMOLE_HOME/extensions/` 에 둔다 (`gc-web/extension/ExtensionModule.java:69,75`). `guac-manifest.json` 의 `authProviders`, `listeners` 로 클래스를 선언한다 (각 확장의 `guac-manifest.json` 에서 확인).
- 로딩 순서는 `extension-priority` 속성으로 지정하고 나머지는 파일명 순 (`ExtensionModule.java:100-107`). 특정 provider 의 내부 실패를 무시하는 `skip-if-unavailable` (91).
- 체이닝 방식 (`gc-web/rest/auth/AuthenticationService.java`):
  1. `authenticateUser`: provider 를 순서대로 돌며 첫 번째 non-null `AuthenticatedUser` 를 채택(128–134). 모두 실패하면 처음 실패(또는 insufficient 우선)를 보고(135–148).
  2. `getUserContexts`: 인증에 성공한 사용자를 **모든** provider 에 넘겨 `getUserContext` 를 받는다(309–314). 즉 인증원과 데이터 저장소가 분리된다.
  3. 각 UserContext 를 **다른 모든** provider 의 `decorate()` 로 겹겹이 감싼다(324, `DecorationService.java:70-91`).
- 확장별 구현 형태 (manifest 와 클래스에서 확인):
  - 1차 인증 + 저장소: `guacamole-auth-jdbc`(MySQL/PostgreSQL/SQLServer 모듈), `guacamole-auth-ldap`(`LDAPAuthenticationProvider.java:74,82,91` — authenticateUser, getUserContext, decorate 모두 구현), `guacamole-auth-json`, `guacamole-auth-header`, `guacamole-auth-radius`, `guacamole-auth-quickconnect`.
  - SSO: `guacamole-auth-sso` 모듈 `openid, saml, cas, ssl`. OpenID 는 jose4j 로 exp/issuer/audience/서명키/nonce 검증 (`.../openid/token/TokenValidationService.java:92-107`).
  - MFA: `guacamole-auth-totp`, `guacamole-auth-duo`. TOTP 는 `authenticateUser` 가 아니라 `decorate()` 에서 `verifyIdentity` 를 호출한다 (`TOTPAuthenticationProvider.java:68-76`). 즉 MFA 는 "다른 provider 가 만든 컨텍스트를 감싸는 데코레이터"다. IP 기반 bypass/enforce 목록이 있다 (`.../totp/user/UserVerificationService.java:324-348`).
  - 접속 제한: `guacamole-auth-restrict` — `RestrictedConnection extends DelegatingConnection` 이 `connect()` 를 가로챈다 (`RestrictedConnection.java:43,141`). 시간/호스트 제한 예외 클래스 존재.
  - 자격증명 금고: `guacamole-vault` — `VaultUserContext extends TokenInjectingUserContext` (`VaultUserContext.java:61`), `VaultSecretService`(`getValue`, `getTokens`: `VaultSecretService.java:77,105,141`). 구현 모듈은 `guacamole-vault-ksm`.
  - 브루트포스 방어: `guacamole-auth-ban` — provider 가 아니라 **Listener** (`BanningAuthenticationListener.java:165`).
  - 녹화 열람: `guacamole-history-recording-storage` — `HistoryAuthenticationProvider.decorate()`(83) 로 `ConnectionRecord` 를 감싸 녹화 파일을 `ActivityLog` 로 노출.

### 1.5 세션 모델

- 웹 세션: 로그인 성공 시 토큰을 만들고 `GuacamoleSession` 을 `TokenSessionMap` 에 저장 (`AuthenticationService.java:404`). 토큰은 `SecureRandom` 32바이트 (`SecureRandomAuthTokenGenerator.java:37`).
- 세션 타임아웃: `api-session-timeout` 기본 60분 (`gc-web/rest/auth/HashTokenSessionMap.java:65,81`). 1분 주기로 검사하고, 열린 터널이 있는 세션은 만료시키지 않는다(150).
- 터널 수명주기 (`gc-web/tunnel/TunnelRequestService.java`): `connectable.connect(info, tokens)`(216) → `UserTunnel` 로 감싸 세션에 등록(264, 312) → `TunnelConnectEvent`(87–89) → close 시 세션에서 제거하고 `TunnelCloseEvent`(111–114, 290).

### 1.7 보안 추상화

- 인증/권한: 1.3–1.4 참조. 객체 권한 4종 + 시스템 권한 7종. 유효 권한은 그룹 상속 포함(`User.getEffectivePermissions()`).
- 계정 통제 속성 (JDBC 모델 클래스 `ModeledUser/ModeledConnection/ModeledConnectionGroup` 에 정의된 이름, 파일별 귀속은 미확인): `expired, access-window-start, access-window-end, valid-from, valid-until, timezone`, `max-connections, max-connections-per-user, failover-only, guacd-hostname, guacd-port, guacd-encryption`. 진행 중 세션에 접근 시간대를 강제하는 옵션 (`JDBCEnvironment.enforceAccessWindowsForActiveSessions()`, `JDBCEnvironment.java:255`).
- 비밀번호 저장: 32바이트 랜덤 salt (`gc-jdbc/security/SecureRandomSaltService.java:37`) + SHA-256 (`SHA256PasswordEncryptionService.java:46`). 반복 횟수(스트레칭)는 미확인.
- 비밀번호 정책: 최소 길이, 최소/최대 사용 기간, 이력 크기, 대소문자/숫자/특수문자, 사용자명 포함 금지 (`gc-jdbc/security/PasswordPolicy.java:41-143`).
- 자격증명 전달: 연결 파라미터의 `${TOKEN}` 을 연결 직전에 치환 (`AbstractGuacamoleTunnelService.java:545-549`). 표준 토큰에 `GUAC_PASSWORD` 가 포함되어 로그인 비밀번호를 원격지에 재사용할 수 있다. vault 확장은 같은 메커니즘으로 비밀을 주입한다.
- 연결 중 추가 자격증명 요구: `guac_client_owner_send_required` (`client.h:883`), owner 전용 `argv_handler`.
- 게이트웨이↔원격 데스크톱 (RDP):
  - `security` 미지정 시 `GUAC_SECURITY_ANY`(협상) (`settings.c:839-842`). 선택지: `nla, nla-ext, tls, rdp, vmconnect, any`(789–836).
  - `ignore-cert` 기본 0 = **검증함** (768–771). 켜면 검증을 건너뜀 (`rdp.c:695-696`). `cert-tofu`, `cert-fingerprints` 옵션(773–781). 검증 훅은 `rdp.c:852,854`.

### 1.8 비기능

- 프로세스 격리: 연결당 fork + `fexecve` + 독립 프로세스 그룹. 타임아웃 시 그룹 단위 SIGKILL (`proc.c:635` 이후, 734–735, 804–813). 사용자당 스레드(`guacd_user_thread`, `proc.c:95`). 사용자 소켓 fd 는 `socketpair` 로 자식에 넘긴다(`connection.c:213`).
- 인코딩: PNG/JPEG/WebP (`gs/src/libguac/encode-{png,jpeg,webp}.c`, `client.h:941,979,1024`). 적응형 품질: 클라이언트 처리 지연(lag) 20→80ms 에 따라 JPEG/WebP 품질 90→30 선형 조정 (`gs/src/libguac/display-worker.c:134-149`). `force-lossless` 옵션(`settings.c:153`).
- 병렬 인코딩: CPU 수만큼 워커 스레드 (`gs/src/libguac/display.c:80,159`) + 렌더 스레드(`display-render-thread.c:194`).
- 스케일아웃: guacd 주소를 연결/그룹 단위로 지정 가능(속성 `guacd-hostname/port`), 그룹 가중치 분산과 failover, `FailoverGuacamoleSocket`(`AbstractGuacamoleTunnelService.java:558`). 웹 세션 맵은 프로세스 메모리(`HashTokenSessionMap`) — 다중 웹앱 노드 간 세션 공유는 미확인.

### 1.9 이 추상화가 암시하는 요구사항

- 프로토콜 중립 중간 표현이 있어야 한다: 브라우저는 RDP/VNC 를 모르고 단일 instruction 집합만 안다(1.1). 새 프로토콜은 플러그인으로 추가된다.
- 연결 단위 장애·권한 격리가 필요하다: 프로토콜 파서가 신뢰할 수 없는 원격 입력을 다루므로 연결당 프로세스로 분리한다(1.8).
- 인증원, 디렉터리(저장소), 정책(MFA·제한·금고·녹화 열람)을 서로 독립된 확장으로 조합할 수 있어야 한다(1.4).
- 유출 통제는 방향별·기능별 스위치로 연결 정의에 붙어야 하고, 공유 프로필이 이를 더 좁힐 수 있어야 한다(1.5, 1.6).
- 녹화는 화면 스트림 복제로 구현하고, 키 입력·클립보드 포함은 명시적 opt-in 이어야 한다(1.5).
- 연결 이력은 연결 수명주기에 묶여 자동 기록되고, 조회는 별도 감사 권한으로 분리되어야 한다(1.5, 1.7).

## 2. Selkies (Rust 워크스페이스)

주의: 이 클론은 Rust 로 작성된 Selkies 이다(`sk/` 아래 `selkies, selkies-rtc, pixelflux, pcmflux, selkies-wm, selkies-draw, selkies-desktop, pelorus, selkies-turn-rest, ...`; `selkies/Cargo.toml`). 아래 서술 중 "(docblock)" 은 모듈 문서 주석 기준이다.

### 2.1 최상위 구조

```
브라우저(web/selkies-web-core, selkies-dashboard)
   ├─ HTTP(S) 제어면: axum 라우터 + 단일 auth 미들웨어 (sk/selkies/src/http)
   ├─ 데이터면 A: WebSocket  GET /api/websockets  (sk/selkies/src/ws)
   └─ 데이터면 B: WebRTC  시그널링 /api/ws + ICE/DTLS/SRTP/SCTP (sk/selkies/src/webrtc, sk/selkies-rtc)
                    │
        같은 프로세스 안에서 pixelflux(화면 캡처+인코딩), pcmflux(오디오) 를 Rust 크레이트로 링크
                    │
              X11 또는 Wayland 데스크톱 (같은 호스트)
```

- 게이트웨이 프로세스가 따로 없다. 서버가 데스크톱이 도는 호스트(컨테이너) 안에서 화면을 직접 캡처한다 (`sk/selkies/src/lib.rs` docblock 9–13).
- 두 전송 중 하나만 캡처를 소유하도록 supervisor 가 전환한다 (`sk/selkies/src/server/mod.rs` docblock 7–8). 기본 모드는 `websockets` (`sk/selkies/src/settings/table.rs:1171`).
- WebSocket 와이어 (docblock, `sk/selkies/src/ws/protocol.rs` 11–19): 텍스트 프레임 = 제어 verb, 바이너리 첫 바이트로 타입 구분 — `0x01` Opus 오디오, `0x02` 마이크, `0x03` JPEG, `0x04` 비디오 스트라이프, `0x05` gzip 제어 텍스트, `0x06` 웹캠 프레임, `0x07` 패딩.
- WebRTC 스택은 자체 구현 계층: `ice, dtls, srtp, sctp, sdp, rtp, signaling, crypto(AWS-LC)` (`sk/selkies-rtc/src/lib.rs` docblock 9–16).

### 2.3 확장점

- 새 전송: `StreamingService` 를 구현해 supervisor 에 등록.
- 새 인코더: pixelflux 의 `encoders/` 에 백엔드 추가. 선택은 `encoder` 설정(`table.rs:1423`, 기본 `h264enc`; help 문자열에 h265enc, vp8enc, vp9enc, av1enc, jpeg 언급).

### 2.4 세션 모델

- 서버 1개 = 데스크톱 1개. 다중 사용자는 같은 데스크톱에 붙는 "페이지"들이다.
- 디스플레이마다 owner 1명. 공유가 켜져 있으면 다른 탭의 controller 가 owner 옆에 합류하고, owner 페이지가 숨겨지거나 유휴 상태면 소유권이 넘어간다 (docblock, `sk/selkies/src/ws/server.rs` 19–24).

- 세션 목록/강제 종료: `Supervisor::sessions()`, `disconnect_session()` (`http/mod.rs:286-290`). 세션 항목 키는 `id, transport, role, slot, display, connected_at, rtt_ms`.

- 동시 접속 수 상한 설정: 미확인.

### 2.6 보안 추상화

- 인증 계층 (docblock, `http/auth.rs` 9–36): (1) Basic 인증 — 기본 켜짐(`table.rs:1311`), 비밀번호가 없으면 **기동 거부** (`http/mod.rs:248-259`, 코드 확인). (2) master token = "보안 모드", 제어면 API 보호(`table.rs:1213`). (3) 세션 토큰 테이블 — 역할·게임패드 슬롯·키보드/마우스 권한 보유. (4) WebSocket 핸드셰이크용 서명 쿠키(HttpOnly, SameSite=Strict).
- 비교는 상수 시간 (`http/auth.rs:108-109` `ct_eq`, 사용처 130, 216, 629).
- 토큰은 스스로 만료되지 않고 다음 테이블에서 빠질 때까지 유효하다. tokens 파일은 2초 주기로 폴링하며 소유자/쓰기 권한을 검사한다 (docblock, `http/tokens.rs` 15–20; 상수 `TOKENS_FILE_POLL` 은 `tokens.rs:43` 부근).
- MFA: 미확인. 세션 유휴 타임아웃: 미확인. 브루트포스 차단: 미확인.
- CSRF/교차 출처: 교차 사이트 WebSocket 업그레이드를 Origin 으로 거부(`allowed_origins` 기본은 same-origin 만, `table.rs:2741`), 모든 응답에 `Content-Security-Policy: frame-ancestors`(기본 `'self'`, 2755).
- TLS: `enable_https` 기본 False (`table.rs:1241`). 켜면 인증서가 없을 때 자체 서명 P-256 인증서를 만들고, 파일 변경 시 핫 리로드 (docblock, `http/tls.rs` 7–18).
- 미디어 구간: WebRTC 는 DTLS/SRTP 모듈 보유 (`sk/selkies-rtc/src/{dtls,srtp}`). TURN 자격증명은 REST 서비스/공유 비밀/Cloudflare 등으로 발급 (`table.rs:1941-2109, 2235-2263`).
- 기본 바인드: `addr` 기본 `localhost`, 전체 인터페이스는 `--public` 명시 필요 (`table.rs:20,34`).
- 권한 모델: 3단 역할 + 토큰별 입력 권한. 객체 단위 ACL 은 없다(대상이 데스크톱 1개).
- 추가 표면: `computer_use_bind`/`computer_use_token`(1815, 1829), `pelorus` 에이전트 설정(2585 이하) — 별도 토큰으로 보호된다고 docblock 에 기술. 상세 미확인.

### 2.7 비기능

- 프로세스 모델: 단일 프로세스, tokio 태스크가 소켓을 소유하고 캡처/오디오 라이브러리는 자체 스레드에서 broadcast 채널로 프레임을 넘긴다. 캡처 콜백은 소켓을 건드리지 않는다 (docblock, `sk/selkies/src/ws/mod.rs` 24–29). 연결당 프로세스 격리는 없다.
- 적응형 품질: `congestion_control` 기본 True — WebRTC 는 transport-wide-cc 피드백, WebSocket 은 프레임 왕복 지연으로 비트레이트 조정 (`table.rs:2473` help). `enable_rate_control`(440), `video_bitrate`(412), `video_crf`(398), `framerate`(384), paint-over 품질 설정(1521–1563).
- 하드웨어 인코딩: NVENC/VA-API 우선, 소프트웨어 폴백 (`table.rs:1423` help; `sk/pixelflux/src/encoders/`).
- 백프레셔: 디스플레이별 relay 의 유한 큐(docblock), 오디오 큐 깊이 `backpressure_queue_size` 기본 120 (`table.rs:2727`).
- 관측: Prometheus `/api/metrics`, `enable_metrics_http` 기본 False (2713).
- 스케일아웃: 서버 자체에는 없음(데스크톱당 1 인스턴스). `addons/{coturn, turn-rest, coder, ondemand}`, `infra/` 디렉터리가 있으나 내용은 미확인.

### 2.8 암시하는 요구사항

- 데스크톱 측 에이전트형 스트리머는 "한 세션 = 한 프로세스"이므로, 사용자·권한·세션 배정은 바깥 플랫폼이 맡고 스트리머는 토큰 테이블을 받아 집행만 한다(2.3, 2.6).
- 전송 계층(WebSocket/WebRTC)을 바꿔도 입력 권한·클립보드 정책·감사가 동일해야 한다 — 공용 모듈로 뽑아 두 전송이 공유한다(2.2, 2.4).
- 모든 정책 설정은 하나의 스키마에서 선언되고, 운영자가 값을 "잠가" 클라이언트가 바꾸지 못하게 할 수 있어야 한다(2.2).
- 감사는 내용이 아니라 메타데이터를 내보내고, 수집기 장애가 세션을 멈추게 하면 안 된다(2.4).

## 3. KasmVNC

### 3.1 최상위 구조

```
브라우저(kasmweb = noVNC 포크, git submodule)
```

### 3.6 보안 추상화

- 인증: WebSocket/HTTP 핸드셰이크의 `Authorization: Basic` (`websocket.c:2022-2037`). `.kasmpasswd` 의 해시와 대조. 해시는 `crypt_r` (`kv/unix/kasmvncpasswd/kasmpasswd.c:41,56`), 알고리즘/솔트 형식은 미확인.
- 권한: 사용자별 `read / write / owner` 3비트 → `AccessRights` 비트마스크. `owner` 만 `/api/` 호출 가능 (`websocket.c:2107-2111`). "writer 는 항상 read 가능" (`VNCSConnectionST.cxx:1386-1388`).
- MFA: 미확인.
- 브루트포스: IP 블랙리스트 — `BlacklistThreshold` 기본 5회, `BlacklistTimeout` 기본 10초(초기값) (`kv/common/rfb/Blacklist.cxx:23-30`); 핸드셰이크 진입 시 검사 (`websocket.c:2010`). YAML `security.brute_force_protection.*`.
- TLS: 서버 내장 OpenSSL (`websocket.c:295`, `SSLv23_server_method`). 최소 프로토콜 버전 설정은 미확인. `sslOnly` 의 C++ 기본은 false (`vncExtInit.cc:102`) 이지만 YAML 기본은 `require_ssl: true`, 기본 인증서는 배포판 snakeoil (`kasmvnc_defaults.yaml`).
- HTTP 응답 헤더 기본값: `Cross-Origin-Embedder-Policy=require-corp`, `Cross-Origin-Opener-Policy=same-origin` (`kasmvnc_defaults.yaml`).
- 기본 바인드: `network.interface: 0.0.0.0` (`kasmvnc_defaults.yaml`).
- TURN 자격증명: 파일은 group/other 권한이 없어야 하고 명령행으로 받지 않는다. 단기 자격증명은 HTTPS 엔드포인트에서 JWT 로 받는다 (`ServerCore.cxx:368-384`). `TurnCredentialSkipVerify` 기본 false.
- 환경변수로 설정을 덮어쓰는 것은 기본 금지 (`server.allow_environment_variables_to_override_config_settings: false`).

### 3.7 비기능

- 프로세스 모델: 데스크톱당 Xvnc 1 프로세스. 웹 서버는 별도 스레드 (`kv/common/network/TcpSocket.cxx:724`), 핸드셰이크 처리에 서브스레드 생성 (`websocket.c:2271`). 연결당 프로세스 격리 없음.

- 비디오 코덱: `videoCodec` = auto, h264, h264_vaapi, h265, h265_vaapi, av1, av1_vaapi (`ServerCore.cxx:405-407`), `VideoQualityCRFCQP 17`(309), `WebRTCMaxBitrate`(313).
- NAT 통과: STUN/TURN/`publicIP`/포트 범위/`ForceTurn` (321–388).
- 스케일아웃: 서버 자체에는 없음. 외부 오케스트레이터(Kasm Workspaces) 연동 흔적은 `KASM_API_JWT` 환경변수 언급뿐이며 상세 미확인.

### 3.8 암시하는 요구사항

- DLP 는 독립된 설정 군으로 다뤄져야 한다: 클립보드(방향·크기·빈도·MIME), 키 입력 속도, 가시 영역, 워터마크, DLP 로그가 하나의 네임스페이스에 모여 있다(3.5).
- 워터마크는 사용자명·시각을 담은 동적 텍스트를 서버 측에서 프레임에 합성해야 한다(클라이언트에서 지울 수 없게).
- 클라이언트가 바꿀 수 있는 설정의 화이트리스트가 필요하다(3.5).
- 사용자 권한은 최소 view / control / admin 3단으로 나뉘고, 관리 API 는 admin 에게만 열린다(3.6).

## 4. 프로젝트를 가로지르는 공통 패턴과 차이

### 4.1 공통 패턴

1. **핸들러 등록 = 권한 집행.** 읽기 전용·클립보드 차단을 "입력 핸들러를 등록하지 않는다 / 비트를 검사한다"로 서버 측에서 집행한다. guacamole `rdp/user.c:89-110`, KasmVNC `VNCSConnectionST.cxx:847,988,1270`, selkies `input/authority.rs`(docblock). 클라이언트(브라우저)는 신뢰하지 않는다.
2. **클립보드는 방향별로 독립 통제.** guacamole `disable-copy`/`disable-paste`, selkies `enable_clipboard=in|out`, KasmVNC `SendCutText`/`AcceptCutText`. 세 프로젝트 모두 **기본값은 양방향 허용**이다.
3. **owner + 참여자 모델.** 세션에는 소유자가 1명 있고 나머지는 축소된 권한으로 합류한다. guacamole `guac_user.owner` + SharingProfile, selkies 디스플레이 owner + Role, KasmVNC `owner` 비트 + shared/exclusive.
4. **전송 추상화 뒤에 인코더 계층.** `guac_socket` / `StreamingService`+`CaptureHandle` / `Encoder`+`SConnection`. 인코더는 교체 가능하고 품질은 링크 상태에 따라 조정된다.
5. **설정은 선언적 스키마.** guacamole 프로토콜 JSON + `GUAC_*_CLIENT_ARGS`, selkies `DEFINITIONS` 테이블, KasmVNC `Parameter` 객체 + YAML 매핑.
6. **녹화·민감 로깅은 opt-in.** guacamole 키/클립보드 미포함 기본, KasmVNC `DLP_Log off`, selkies 녹화는 명시적 API 호출.
7. **마이크·웹캠·명령 실행 같은 역방향/고위험 채널은 기본 차단.** guacamole `enable-audio-input 0`, `enable-drive 0`, `enable-printing 0`; selkies `microphone_enabled/webcam_enabled/command_enabled False`.

### 4.2 차이

| 축 | Guacamole | Selkies | KasmVNC |
|---|---|---|---|
| 배치 위치 | 원격지와 분리된 게이트웨이(프로토콜 변환) | 데스크톱 호스트 내 스트리머 | 데스크톱 호스트 내 X 서버 겸 스트리머 |
| 원격 프로토콜 | RDP/VNC/SSH/telnet/k8s/serial 플러그인 | 없음(직접 캡처) | 없음(직접 프레임버퍼), 수정 RFB |
| 브라우저 와이어 | Guacamole instruction (텍스트) over HTTP/WS | WS 바이너리 opcode 또는 WebRTC | WS 위 수정 RFB + WebRTC |
| 사용자/연결 관리 | 내장(디렉터리, 권한, 그룹, 이력) | 없음(토큰 테이블 주입) | 최소(passwd 파일 + owner API) |
| 인증 확장 | 플러그인 체인 + 데코레이터(LDAP/OIDC/SAML/CAS/RADIUS/TOTP/Duo/vault) | 내장 gate 1개(Basic, master token, 세션 토큰) | Basic 1종, 끄고 위임 가능 |
| 권한 모델 | 객체 권한 4종 × 6객체 + 시스템 권한 7종 | 역할 3단 + 토큰별 입력 권한 | read/write/owner 3비트 |
| 격리 | 연결당 프로세스 | 단일 프로세스 | 단일 프로세스 |
| 워터마크 | 미확인 | 정적 PNG burn-in | 이미지 + 동적 텍스트 |
| 파일/프린터 기본값 | 드라이브·프린터 **차단** | 파일·프린터 **허용** | 미확인 |
| 감사 | DB 연결 이력 + 녹화 + 이벤트 리스너 | 웹훅(메타데이터) | 로그(DLP_Log), API 조회 |
| 브루트포스 방어 | 확장(IP 5회/300초) | 미확인 | 내장 IP 블랙리스트(5회/10초) |
| 세션 타임아웃 | 웹 세션 60분(터널 있으면 유지) | 미확인 | Idle/MaxConnection/MaxIdle 파라미터 |
| 내부 구간 암호화 기본 | 웹앱↔guacd 평문 | 단일 프로세스(해당 없음), HTTPS 기본 꺼짐 | YAML 기본 `require_ssl: true` |

읽는 법: Guacamole 은 "여러 원격지를 중개하는 관리형 게이트웨이", Selkies·KasmVNC 는 "데스크톱 한 대에 붙는 스트리밍 에이전트"다. DaaS 제품은 보통 둘을 합친다 — 관리면(사용자·배정·권한·이력)은 Guacamole 형, 데스크톱 내 집행 지점(DLP·워터마크·인코딩)은 KasmVNC/Selkies 형.

## 6. 미확인 항목 (후속 확인 필요)

- Guacamole: 워터마크 기능 유무, USB 리디렉션 통제 파라미터, 공유 키 만료 정책, 다중 웹앱 노드 간 세션 공유, guacd 의 클라이언트 인증, VNC 구간 TLS 옵션, `max-connections` 값 0 의 의미, JDBC 모델 속성의 파일별 귀속, `ConnectionGroup.Type` 의 나머지 값, `guacenc`/`guaclog` 내부 동작, 프런트엔드(JS) 쪽 통제 로직 전체, `guac_client_init` 의 typedef 와 실제 시그니처 불일치 이유.
- Selkies: docblock 으로만 읽은 항목의 구현 본문(인증 gate 분기, owner 이전, 감사 큐, 파일 confinement), MFA·세션 타임아웃·브루트포스 방어·동시 접속 상한 유무, 동적 텍스트 워터마크 유무, `addons/`·`infra/` 의 스케일아웃 구성, `computer_use`/`pelorus` 표면의 보안 경계.
- KasmVNC: 세션 녹화 유무, 파일 업로드·프린터·오디오 통제, `crypt_r` 해시 알고리즘, TLS 최소 버전, 브라우저 경로에서 쓰이는 `SSecurity` 조합, `unix_relay` 의 용도, 외부 오케스트레이터 연동, `kasmweb`(프런트엔드 submodule) 내용.
