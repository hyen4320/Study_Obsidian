# 오케스트레이터

> 한 줄 정의: **오케스트레이터는 별도 프로그램이 아니라, 사용자와 대화하는 메인 세션 그 자체이며, 하는 일은 "쪼개고 – 나눠주고 – 받고 – 합치기" 네 가지뿐입니다.**

상세 흐름·구성 예시: [[멀티에이전트 오케스트레이션 정리]] · 짝 개념: [[멀티 에이전트]]

## 하는 일 4단계

1. **분해(Decompose)** — 요청을 독립적으로 끝낼 수 있는 단위로 쪼갬
2. **위임(Dispatch)** — 단위마다 맞는 에이전트를 골라 프롬프트를 만들어 던짐
3. **수집(Collect)** — 반환된 요약을 받음 (원본 파일 내용은 올라오지 않음)
4. **병합(Synthesize)** — 모순을 조정해 최종 산출물로 합침

## 핵심 원칙

- **직접 일하지 않습니다.** 오케스트레이터가 코드를 읽고 쓰기 시작하면 컨텍스트가 오염되어 병합 능력을 잃습니다.
- **의존성 그래프가 전부입니다.** 의존 없는 작업은 같은 층 → 동시 호출, 의존 있는 작업은 다음 층 → 순차 실행.
- **컨텍스트를 복사해서 넣어야 합니다.** 서브에이전트는 이 대화를 보지 못하므로, 필요한 정보는 프롬프트에 직접 넣습니다.
- **검증을 위임해야 합니다.** 요약만 받으므로 스스로 검증할 수 없습니다. `verifier` 에이전트가 원본을 다시 읽게 합니다.

## 오케스트레이션 프롬프트 골격

```
너는 오케스트레이터다. 직접 코드를 읽거나 쓰지 마라.
1. 요청을 독립 작업으로 쪼개고 의존성 그래프를 먼저 출력해라.
2. 의존성이 없는 작업은 한 번에 동시 호출해라.
3. 각 서브에이전트에 필요한 컨텍스트를 프롬프트에 직접 넣어라.
4. 모든 구현 작업 뒤에는 verifier를 반드시 붙여라.
5. 마지막에 결과를 병합해 하나의 md로 남겨라.
```

## 동적 오케스트레이션 vs 워크플로

| 구분 | 동적 오케스트레이션 | 워크플로(스크립트) |
| --- | --- | --- |
| 순서 결정 | 그때그때 판단 | 코드에 고정 |
| 재현성 | 매번 다를 수 있음 | 동일 입력 → 동일 경로 |
| 적합 | 탐색적 작업 | 반복 작업(리뷰 파이프라인, 보고서 생성) |
