# 멀티에이전트 오케스트레이션 구축 가이드 (배포용 v2 · 토큰 절약 버전)

작성일: 2026-09-11 · 원본 환경: 클라우드에어 「서화」 개발 관제(`C:\work\seohwa-agents`) · 대상 독자: **Claude Code를 써서 같은 구조를 자기 프로젝트에 구축하려는 사람**

## 결론

이 가이드대로 하면 **판단은 Fable, 구현은 Opus, 정해진 명령·잡일은 Haiku**로 나뉜 worktree 기반 멀티에이전트 관제를 반나절 안에 세울 수 있다. 사람이 손으로 짜는 것은 거의 없다. 각 단계의 "Claude에게 줄 지시문"을 Claude Code에 그대로 붙여 넣으면 Claude가 스크립트·역할 파일·서브에이전트를 만든다. 전부 Fable로 돌리는 v1 대비 비용은 50~65% 줄고, 산출물 품질은 verify → 리뷰 → 통합 게이트가 그대로라 차이가 없다. 품질을 지키는 조건은 하나, **Fable이 필요한 순간(2회 실패·리팩토링·구조 판단·문서 검토)에 빠짐없이 불리도록 규칙으로 고정하는 것**이다. 그리고 에이전트를 돌리기 전에 **2-0 최초 세팅(보호 브랜치·기준선 태그·exclude·경계 훅)** 을 반드시 먼저 끝낸다. 이것이 없으면 에이전트가 메인 브랜치를 건드리고 되돌릴 방법이 없다.

### 채우는 순서

**최초 1회만 묻는다.** `fleet-init.sh` 를 실행하면 0단계에서 `.fleet/config.env` 를 보고, **파일이 없거나 크기가 0이면** 질문을 시작해 값을 채운 뒤 다음 단계로 넘어가고, **크기가 0이 아니면 질문 없이 통과**한다. 사람이 파일을 직접 채우는 일은 없다. 이미 채워진 파일을 다시 묻게 하려면 `fleet-init.sh --reconfigure` 로 돌리거나 파일을 비운다.

1. `scripts/fleet-init.sh` 실행. 0단계가 감지 가능한 값을 먼저 채우고(`HOST_IP` `DEV_BRANCH` `BASELINE_COMMIT` 후보 `FE_DIR`/`BE_DIR` `USE_ALEMBIC` `FE_I18N_DIRS` `BE_COMPOSE_SERVICE` `ENV_TEMPLATE` `REMOTE_NAME` `DIRTY_EXCEPT` 후보), 판단이 필요한 값만 묻는다(`BASELINE_COMMIT` 확정 — "이 커밋 이전은 건드리지 않습니까?" / `PROTECTED_BRANCHES` / `HOTSPOTS` / 사무 저장소 사용 여부 / 모델 ID). 감지값이 맞으면 Enter 로 넘어간다.
2. 질문이 끝나면 채운 값·비운 값을 표로 보여 주고 확인을 받은 뒤 `config.env` 에 쓴다. 이때부터 파일 크기가 0이 아니므로 다음 실행부터는 이 단계를 건너뛴다.
3. (2) `DEV_BRANCH`·`BASELINE_COMMIT`·`PROTECTED_BRANCHES` 가 **"어디까지는 건드리지 않는가"를 정하는 값**이므로 표에서 이 셋만은 눈으로 확인한다.
4. (3) 에서 자기 스택에 없는 것(`BE_DIR`, `USE_ALEMBIC`, `FE_I18N_DIRS`, `HOTSPOTS`)은 감지 단계에서 빈 값이 되고, 빈 만큼 verify·락·티어 판정이 단순해진다.
5. (4)·(5) 는 기본값으로 시작하고 1~2일 운영 뒤 `config.env` 를 직접 고친다(그 뒤로는 묻지 않으므로 파일 편집이 곧 설정 변경).
6. (6) 은 사무 저장소 사용 여부를 y 로 답했을 때만 이어서 묻는다.

| 프론트 | `fe-explore` `fe-verify` `fe-summarize` | Haiku | 탐색 / 검증 실행·실패 요약 / diff·로그 요약 |
| 프론트 | `fe-hard` | Fable | 어려운 작업 전담(조건부) |
| 백엔드 | `be-explore` `be-verify` `be-summarize` | Haiku | 위와 동일 |
| 백엔드 | `be-hard` | Fable | 어려운 작업 전담(조건부) |
| 문서 | `doc-find` `doc-check` | Haiku | 자료 검색·발췌 / 형식·필수절·기밀 점검 |
| 문서 | `doc-judge` | Fable | 구성·증빙·심사 기준 검토, **지시만** (Write 없음) |

### 1.4 흐름

```
fe/be:   task-new → wt-new → [explore(Haiku) → DEV(Opus) → verify(Haiku)] ×n → (2회 실패 시 *-hard(Fable)) → summarize(Haiku) → review-req → REVIEWER → integrate → push(사람)
office:  task-new → wt-new → [doc-find(Haiku) → OFFICE(Opus 1M) → doc-check(Haiku) → doc-judge(Fable)] ×n → verify → review-req → publish
```

제약: Claude Code 서브에이전트는 다른 서브에이전트를 부를 수 없다. 그래서 DEV 세션(최상위)이 자기 worktree의 서브에이전트를 부르고, 헤드리스 루프는 프롬프트에 "탐색은 `*-explore`, 검증은 `*-verify`에 위임"을 박아 넣는다.

### 2-0. 최초 세팅 — 건드리면 안 되는 것과 안전장치 (가장 먼저, 한 번만)

에이전트를 돌리기 전에 **사람이 직접 정하고 잠가 두는 것**들이다. 여기서 정한 것은 이후 스크립트(`guard-path.sh` · `settings.local.json` deny · `integrate.sh`)가 강제하므로, 빠뜨리면 에이전트가 메인 브랜치를 건드리거나 되돌릴 수 없는 상태가 된다.

#### (1) 보호 대상 — 절대 직접 수정·커밋하지 않는 것

| 대상 | 규칙 | 강제하는 곳 |
| --- | --- | --- |
| 메인 저장소 `C:\work\<프로젝트>` 워킹트리 | **읽기 전용 기준점.** 모든 작업은 `wt/<ID>/` worktree 에서만 | `guard-path.sh`(쓰기 차단) · 역할 파일 |
| 개발 브랜치 `dev-ryu` `development`(원본 기준) | 직접 커밋 금지. 통합은 `integration` 으로만 | `integrate.sh` 가 `integration` 에만 `--no-ff` 머지 |
| 사무 저장소 `main` | 직접 커밋 금지. `office-publish.sh` 만 예외 | `guard-path.sh`(사무 저장소 main 작업본 차단) |
| 원격 `origin` | **push 는 사람이 직접.** 에이전트 `git push` 금지 (`LOOP_AUTO_PUSH=0` 으로 시작) | `settings.local.json` deny `Bash(git push*)` |
| Obsidian 볼트 | 읽기만 | `guard-path.sh` |
| 사용자 원본 자료(바탕화면 등) | 옮기지도 고치지도 않음. `입력/<ID>/` 에 복사본 | 역할 파일 · verify |
| `package.json` `package-lock.json` `requirements.txt` `docker-compose.yml` `.gitignore` `.gitattributes` | 에이전트 수정 금지. 의존성 추가는 오케스트레이터가 메인 작업본에서만 | deny `npm install*` `pip install*` · 리뷰 게이트 |
| `.env` `.env.local` `CREDENTIAL_KEY` | 읽기·출력 금지 | deny `Read(**/.env)` |
| `backend/data/` `terraform/` `migrations/`(스키마 변경 카드 외) | 수정 금지 | 범위 검사 · `alembic` 락 |
| git 명령 `checkout` `switch` `rebase` `reset --hard` `stash` `worktree` `filter-branch` `--force` | worktree 안에서 금지 | deny 목록 |

`integration` 브랜치가 **유일한 통합 지점**이다. 사람은 `integration` 을 확인한 뒤 개발 브랜치로 옮기거나 push 한다.

#### (2) 되돌릴 수 있게 — 기준선 태그와 번들

시작 시점의 메인 저장소에 `fleet-baseline-<YYYYMMDD-HHMM>` 태그를 찍고 `git bundle create … --all` 로 `.fleet/backup/` 에 전체 백업을 남긴다. 무엇이 꼬여도 `git reset --hard fleet-baseline-…`(사람이, 메인 작업본에서) 또는 번들 복원으로 돌아갈 수 있다. 워킹트리가 깨끗한 상태(미커밋 변경 없음)에서만 찍는다.

#### (3) 메인 저장소에 남기지 않는 파일 — `.git/info/exclude`

`.gitignore` 는 건드리지 않고 `.git/info/exclude` 에 다음을 넣는다: `/CLAUDE.md` `/CLAUDE.local.md` `.claude/` `.fleet-port` `backend/docker-compose.override.yml` `/build/`. worktree 마다 생기는 역할 파일·설정·포트 파일이 커밋에 섞이는 것을 막는다.

#### (4) 환경 파일

`backend/.env` 가 없으면 `.env.development` 에서 복사하고 `CREDENTIAL_KEY` 가 비어 있으면 생성해 채운다(값은 출력하지 않는다). worktree 는 이 파일을 복사해 `COMPOSE_PROJECT_NAME` 만 바꿔 쓴다. 프론트 `.env.local` 은 `NEXTAUTH_URL` 만 포트에 맞게 바꿔 복사한다.

#### (5) WSL·drvfs 특이사항 (원본 환경 그대로)

- `/mnt/c` 의 파일 소유자가 root 라 git 이 `dubious ownership` 을 내므로 스크립트가 저장소·worktree 경로를 전역 `safe.directory` 에 등록·해제한다.
- venv 는 `/mnt/c` 에 만들 수 없어(`chmod` 실패) 실체를 `~/.local/share/<프로젝트>-fleet/venv` 에 두고 `<관제>/.venv` 는 심볼릭 링크로 건다.
- 사무 저장소는 리눅스 FS 에서 `git init` 한 `.git` 을 복사해 만들고 `.git/config` 에 `filemode=false` 를 직접 쓴다. drvfs 저장소에서는 `git config` 쓰기 명령이 실패한다.
- `/etc/wsl.conf` 에 `[automount] options="metadata"` 를 넣고 `wsl --shutdown` 후 다시 연다. 안 하면 Next 16 Turbopack 빌드가 `.next/` 쓰기에서 실패한다.

#### (6) 세션 경계 — Claude Code 설정

worktree 마다 `.claude/settings.local.json` 에 deny 목록(위 표의 git 명령 · `npm install*` · `pip install*` · `Read(**/.env)`)과 `PreToolUse` 훅(`Edit|Write|MultiEdit` → `guard-path.sh`)을 넣는다. 훅은 권한 모드와 무관하게 항상 실행되므로 헤드리스(`--permission-mode bypassPermissions`)에서도 경계가 지켜진다. `guard-path.sh` 는 편집 대상이 카드 `scope` 밖 · 메인 저장소 · 볼트 · 다른 worktree · 사무 저장소 main 이면 exit 2 로 차단하고, `.fleet/debt.md` 와 `.fleet/adr/` 만 어느 세션이든 허용한다.

#### (7) 사무 저장소 2개

`C:\work\<프로젝트>-office`(프로젝트 사무, `OF-`) 와 `C:\work\office`(일반 사무, `GO-`) 를 만든다. 구조는 `입력/<ID>/` · `작업/<종류>/<ID>/` · `산출물/<ID>/`. 각 저장소 루트에 문서 규칙 `CLAUDE.md` 를 두고 `.git/info/exclude` 에 `/CLAUDE.local.md` `.claude/` `/build/` 를 넣는다. `OFFICE_SEOHWA` 가 비어 있으면 이 단계 전체를 넘어간다.

```
4) scripts/agent-run.sh TASK-SMOKE-001 dev 를 실행하고 .fleet/logs/TASK-SMOKE-001/ 의 로그에서 --model opus 로 기동했는지, 완료 보고 마지막 줄에 서브에이전트 호출 횟수가 있는지 확인하십시오.
5) 세 번째 기동을 흉내 내기 위해 echo 3 > .fleet/run/TASK-SMOKE-001.tries.dev 를 한 뒤 agent-run.sh 를 다시 돌려 프롬프트에 fe-hard 강제 문구가 들어갔는지 로그로 확인하십시오.
6) 끝나면 scripts/wt-rm.sh TASK-SMOKE-001 로 정리하십시오.
```

여기까지 통과하면 구축 완료다. `~/.claude/agents/` 에 세션 공용 서브에이전트(`fleet-reviewer` model: opus · `fleet-qa` `fleet-integrator` model: sonnet)를 두면 루트 세션에서도 같은 절감이 된다.

## 5. 자주 막히는 곳

- **모델 ID 오류로 기동 실패**: `claude --model claude-fable-5-1 -p "hi"` 로 단독 확인. 계정에 Fable 이 없으면 `MODEL_ORCH` `MODEL_HARD` 를 `opus` 로 내리고 나머지는 그대로 둔다(그래도 절감의 대부분은 유지된다).
- **서브에이전트가 안 불림**: description 에 "반드시 호출하십시오" 조건이 있는지, worktree 의 `.claude/agents/` 에 복사됐는지 확인. 서브에이전트는 서브에이전트를 못 부르므로 DEV 세션이 직접 불러야 한다.
- **Opus 1M 이 비싸짐**: 20만 토큰을 넘는 컨텍스트는 단가가 오른다. 문서·디자인 외에는 `opus` 를 쓴다. 문서도 `doc-find` 가 발췌를 잘 하면 20만을 넘길 일이 드물다.
- **drvfs 에서 chmod 실패**: `/etc/wsl.conf` 의 `metadata` 옵션 후 `wsl --shutdown`.
- **Next 16 + 링크된 node_modules 거부**: worktree 마다 `npm ci`(느림) 또는 메인 node_modules 복사 + 리눅스 네이티브 패키지 보충. `wt-new.sh` 가 자동 처리하도록 되어 있다.
- **Alembic heads 2개**: `alembic` 락을 잡지 않고 두 카드가 동시에 리비전을 만든 경우. 카드에 `schema_change: true` 가 없으면 락이 거부되도록 `lock.sh` 를 짠다.
