# 멀티 에이전트

> 한 줄 정의: **서브에이전트는 독립된 컨텍스트를 가진 일회용 LLM 인스턴스이며, 멀티에이전트는 병렬화 기법이기 이전에 컨텍스트 절약 기법입니다.**

상세 흐름·구성 예시: [[멀티에이전트 오케스트레이션 정리]] · 짝 개념: [[오케스트레이터]]

## 왜 쓰는가

핵심 자원은 시간이 아니라 **컨텍스트 윈도우**입니다. 파일 100개를 읽어야 하는 일을 서브에이전트에 맡기면, 메인 세션은 **요약 20줄만** 소비합니다.

| 한계 | 해결 방식 |
| --- | --- |
| 컨텍스트 한도 | 더러운 일은 서브에이전트 컨텍스트에서 태우고 요약만 회수 |
| 직렬 처리 | 독립 작업 동시 실행 |
| 역할 혼선 | 관점마다 다른 시스템 프롬프트를 가진 에이전트를 분리 |

## 서브에이전트의 성질 4가지

- **격리** — 메인 대화를 모름. 프롬프트에 넣어준 것만 앎
- **일회성** — 끝나면 컨텍스트 소멸. 다음 호출은 완전히 새 인스턴스
- **단방향** — 에이전트끼리 직접 대화 불가. 반드시 오케스트레이터 경유
- **텍스트 반환** — 마지막 메시지 한 덩어리만 결과로 올라옴

## 정의 파일 형식

`.claude/agents/<이름>.md` (프로젝트) 또는 `~/.claude/agents/<이름>.md` (전역)

```markdown
---
name: backend-reviewer
description: FastAPI 백엔드 코드를 읽고 문제를 지적한다. 코드는 수정하지 않는다.
tools: Read, Grep, Glob
model: sonnet
---

## 범위
- backend/app 하위만 본다. frontend는 열지 않는다.

## 규칙
- 수정하지 않는다. 추측하지 않는다. 근거 파일·줄번호를 붙인다.
- 확인 불가 항목은 "불명"으로 표시한다.

## 반환 형식 (이 표만 반환)
| 파일:줄 | 문제 | 심각도 | 근거 |
```

- `description`이 **에이전트 선택 기준**입니다. 모호하면 엉뚱한 에이전트가 뽑힙니다.
- `tools`를 좁히는 것이 안전장치입니다. 조사용에 Write를 주면 시키지 않은 파일을 만듭니다.

## 팀 비유가 깨지는 지점

| 사람 팀 | 에이전트 | 대응 |
| --- | --- | --- |
| 옆자리에 물어봄 | 대화 불가 | 정보를 프롬프트에 복사 |
| 어제 일을 기억 | 매번 기억 상실 | 상태를 md에 기록 |
| 모르면 되물음 | 추측해서 진행 | "모르면 불명으로 반환" 명시 |
| 중복 회피 | 같은 파일 반복 읽음 | 경로 단위 배타 분할 |

**에이전트를 늘리면 비용은 선형으로 늘지만 품질은 그렇지 않습니다.** 요약 손실이 누적되어 5개 구성이 2개 구성보다 나쁜 경우가 흔합니다.

## 실패 패턴

| 증상 | 처방 |
| --- | --- |
| 결과가 뭉뚱그려짐 | 반환 표 스키마 강제 |
| 같은 일을 두 번 함 | 담당 경로 배타 분할 |
| "완료"인데 안 됨 | verifier 에이전트 필수 |
| 비용만 나가고 느림 | 의존성 그래프 먼저 출력 |
| 엉뚱한 에이전트 선택 | description을 "언제 쓰는지"로 명확히 |
